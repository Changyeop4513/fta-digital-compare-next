# FTA 디지털협정 조항 비교 서비스

한국이 체결한 여러 **FTA(자유무역협정)의 디지털 통상 조항**을 협정별로 나란히 놓고 **원문 그대로** 비교하는 웹 앱입니다.
재정경제부 소관 **3개 주제**만 다루며, 각 조항은 **영문 원문 + 한국어 정본**을 한 쌍으로 보여줍니다.

## 왜 만들었나

디지털 통상 조항은 협정마다 다른 문서에 흩어져 있습니다. 같은 주제라도 협정별 조문을 찾으려면 협정문 PDF를 각각 열어 조항을 찾고, 문서 편집기나 엑셀에 복사해 나란히 붙여놓고 대조해야 합니다.

| 현행 방식의 문제 | 이 앱의 해결 |
|---|---|
| **분산** — 협정마다 문서가 따로라 한눈에 못 봄 | 한 화면에 최대 4개 협정을 좌우로 배치 |
| **수작업 오류** — 복사·붙여넣기 중 조문 누락·오기 | 검증된 데이터를 그대로 렌더링 (사람 손 안 탐) |
| **영·한 짝 관리 번거로움** | 각 칸에 영문 원문 + 한국어본을 항상 한 쌍으로 |
| **버전 혼선** — 지금 보는 게 최신본인지 모름 | 조항마다 **데이터 기준 시점(baseline)** 라벨 표시 |
| **재현성 부족** — 같은 비교를 매번 처음부터 | 주제·협정만 고르면 누구나 동일 화면 재현 |

> 목표: 수작업으로 **20~30분** 걸리던 협정 3~4개 대조를 **3분 이내**로.

**주 사용자:** 재정경제부 내부 실무자 (확장: 통상 실무자·연구자 — 로펌, 연구기관, 무역 전공 대학원생 등)

## 다루는 주제 (3개 고정)

재정경제부 소관 주제만 다룹니다. 임의로 추가·변경하지 않습니다.

| 주제 | 데이터 태그 | 설명 |
|---|---|---|
| **전자적 전송물 무관세** | `customs_duties` | 전자적 전송물에 대한 관세 부과 금지·무관세 관행 유지 |
| **특송화물** | `express_shipments` | 특송화물의 신속 통관 절차 |
| **종이 없는 무역** | `paperless_trading` | 무역 서류의 전자적 제출·수용 |

> 데이터 이전, 소스코드, 개인정보보호 등 **다른 부처 소관 조항은 다루지 않습니다.**

## 수록 현황 (1차 4개 협정 · 총 11개 조항)

주제를 고르면 앱이 협정별 **있음/없음**을 자동 판정해 보여줍니다. 판정은 데이터의 `topic` 태그 기준이며, 임의 추론은 하지 않습니다.

| 주제 | 한-싱가포르 (DPA) | RCEP | 한-영국 | 한-미 (KORUS) |
|---|---|---|---|---|
| **무관세** | ✅ 제14.5조 | ✅ 제12.11조 | ✅ 제7.48조 제3항 | ✅ 제15.3조 |
| **특송화물** | ✅ 제14.13조 | ✅ 제4.15조 | ❌ 해당 조항 없음 | ✅ 제7.7조 |
| **종이 없는 무역** | ✅ 제14.12조 | ✅ 제12.5조 | ✅ 제7.49조 제1항 마호 | ✅ 제15.6조 |

**협정별 데이터 기준 시점(baseline)**

| 협정 | 기준본 |
|---|---|
| 한-싱가포르 | 한-싱 **DPA(디지털동반자협정)** — 서명 2022-11-21 · 발효 2023-01-14 |
| RCEP | 2020-11-15 서명본(법적 검증본) — 한국 발효 2022-02-01 |
| 한-영국 | 한-EU FTA 2011 발효본 조문을 **한-영국 FTA가 승계** (2021-01-01 발효) |
| 한-미 | KORUS — 2019-01-01 개정 발효 기준 (USTR 게재 최종본) |

> 한-영국은 전자상거래 절(제7장 제6절)에 **독립된 특송화물 조항이 없어** "해당 조항 없음"으로 표시됩니다. 무관세·종이 없는 무역도 별도 조문이 아니라 목적·협력 조항의 특정 항에 규정돼 있어, 조항 번호에 해당 항을 함께 명시했습니다.

## 주요 기능

### 1. 조항별 협정 비교 뷰
- 최대 **4개 협정**을 좌우로 나란히 표시 (1개만 고르면 한 칸만, 초과 선택 불가)
- 좌우 배치 순서는 **사용자가 고른 순서**를 그대로 따름
- 각 칸 = `조항 번호 · 기준일 라벨 · 영문 원문(EN) · 한국어본(KO)`
- 한 협정에 같은 주제 조항이 여러 개면 **누락 없이 모두** 조항 번호 순으로 나열
- 긴 원문은 앞부분만 접어 보여주고 **"더보기"**로 전체 펼침

### 2. 주제·협정 선택 + 원문 내 키워드 검색
- 주제는 **라디오(1개씩)**, 협정은 **체크박스(다중, 최대 4개)**
- **주제를 바꿔도 선택한 협정 목록은 유지** — 같은 협정 조합으로 세 주제를 이어서 비교
- 검색은 **현재 선택한 주제·협정 범위 안의 원문에서만** 수행 (전체 데이터 검색 아님)
- **부분 일치** 지원 (예: `무관세` → `무관세화`도 매칭), 영문은 **대소문자 구분 없음**
- 찾은 단어는 **노란 형광펜으로 하이라이트만** — 요약·해석 없음
- 검색어가 포함된 조항 카드는 **자동으로 펼쳐짐**

### 3. 주제별 조항 보유 협정 자동 찾기
- 주제를 고르면 협정별 **있음 / 없음** 배지를 자동 표시
- "있음"인 협정을 바로 골라 비교 뷰로 연결

## 🔒 원문 무결성 원칙 (이 앱의 신뢰성)

이 앱의 가치는 **원문을 손대지 않는 것**에 있습니다.

- 조항 원문(`text_en` / `text_ko`)을 **요약·수정·의역·재작성하지 않습니다.** 준비된 데이터를 그대로 표시만 합니다.
- **AI 요약·해설·해석 기능을 만들지 않습니다.** 이 앱이 하는 일은 원문 비교와 키워드 검색뿐입니다.
- 한국어본이 없으면 임의 번역을 만들지 않고 **"번역 없음"**으로 명시합니다.
- 원문은 **정부 공식 1차 출처(협정문 원본 PDF 등)에서 그대로 확보한 것만** 입력합니다. 검색엔진 요약·2차 설명 자료는 원문으로 쓰지 않습니다.
- 출처·기준일·보정 메모 등 주석은 **`source` 필드에만** 기록하고, 원문 필드에는 원문 외 어떤 표시도 섞지 않습니다.
- 조항 유무를 임의로 추론하지 않고, **데이터에 있는 그대로만** 판정합니다.

## 데이터

조항 1건 = 객체 1개. 전체 데이터는 [`src/data/articles.json`](src/data/articles.json)에 있습니다.

| 필드 | 설명 |
|---|---|
| `agreement` | 협정 한글 약칭 (`한-싱가포르` / `RCEP` / `한-영국` / `한-미`) |
| `topic` | 주제 태그 — `customs_duties` / `express_shipments` / `paperless_trading`. **협정 간 조항을 나란히 묶는 매칭 기준** |
| `article_no` | 조항 번호·제목 (표시용, 매칭에는 사용하지 않음) |
| `text_en` | 영문 원문 |
| `text_ko` | 한국어본 (없으면 빈 값 → "번역 없음"으로 표시) |
| `source` | 출처 (문서명·추출 경로) |
| `baseline_date` | 데이터 기준 시점(버전/기준일) |

**출처 및 검증**

각 조항의 영문·한국어 원문은 아래 **정부·공식 1차 출처**에서 확보하고, **산업통상자원부 FTA 포털** 공식 협정문과 대조해 일치를 검증했습니다.

| 협정 | 영문 원문 출처 | 한국어본 출처 |
|---|---|---|
| 한-싱가포르 | 싱가포르 MTI 게재 공식 영문본 | KSDPA 국문 정본 (한국어·영어 동등 정본) |
| RCEP | 뉴질랜드 외교통상부(MFAT) 법적 검증본 | RCEP 제4·12장 국문본 |
| 한-영국 | 한-EU FTA 전문 (산업통상자원부 게재, 한-영국 FTA가 조문 승계) | 한-영 FTA 국문본 |
| 한-미 | USTR 공식 Final Text | 한-미 FTA 국문본 |

> 다루는 데이터는 정부가 공표한 **공개 협정문**뿐이며 대외비가 아닙니다. **개인정보를 수집·저장·처리하지 않습니다** (로그인 기능 없음).

### 프로젝트 구조

```
my-app/
├─ index.html               앱 진입 HTML
├─ vite.config.js           Vite 설정 + 개발/프리뷰 보안 헤더

   ├─ main.jsx              앱 시작점
   ├─ App.jsx               전체 상태 관리 (주제·협정·검색어)
   ├─ constants.js          대상 협정 목록
   ├─ components/
   │  ├─ TopicSelector.jsx      주제 선택 (라디오, 3개 고정)
   │  ├─ AgreementSelector.jsx  협정 선택 (체크박스, 최대 4개)
   │  ├─ SearchBar.jsx          키워드 검색창
   │  ├─ AvailabilityBar.jsx    협정별 조항 유무 배지
   │  ├─ ComparisonView.jsx     비교 뷰 (선택 협정 좌우 나열)
   │  ├─ AgreementColumn.jsx    협정 1개 = 세로 칸
   │  ├─ ArticleCard.jsx        조항 1건 (번호·기준일·EN·KO·더보기)
   │  └─ EmptyState.jsx         화면 전체 예외 안내
   ├─ data/articles.json     조항 데이터 (11건)
   ├─ assets/                재정경제부 로고 (원본/헤더 반전본)
   └─ styles/index.css       전체 스타일
```

**상태 관리** — 상태는 `App.jsx` 한 곳에서만 관리하고 하위 컴포넌트로 내려줍니다.

| 상태 | 의미 |
|---|---|
| `articles` | 로드된 전체 조항 데이터 |
| `selectedTopic` | 현재 고른 주제 1개 |
| `selectedAgreements` | 고른 협정 목록 (선택 순서 유지, 최대 4) |
| `keyword` | 검색어 |

> 보유 현황·비교 컬럼·하이라이트는 위 4개 상태로부터 **그때그때 계산**합니다(따로 저장하지 않음).

## 배포 · 보안

정적 사이트이므로 어디에나 배포할 수 있습니다.

> 이 저장소는 **Vercel 프로젝트 `fta-digital-compare-next`에 연결**돼 있어 `main` 브랜치에 push하면 [자동 재배포](https://fta-digital-compare-next.vercel.app)됩니다. (1차 사이클 배포본은 별개 저장소 `fta-digital-compare`에서 관리되며 서로 영향이 없습니다.)

[`vercel.json`](vercel.json)이 포함돼 있어 배포 시 아래 **보안 응답 헤더 5종**이 적용됩니다.

| 헤더 | 값 |
|---|---|
| `Content-Security-Policy` | `default-src 'self'` 기반 (외부 스크립트·프레임 차단) |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `SAMEORIGIN` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Strict-Transport-Security` | `max-age=63072000; includeSubDomains` |

> 개발·프리뷰 서버에도 동일한 헤더가 적용됩니다([`vite.config.js`](vite.config.js)). CSP는 HMR과 충돌하므로 프리뷰·프로덕션에만 적용됩니다.
> **비밀 정보(`.env` 등)는 `.gitignore`로 제외**되며 저장소에 올라가지 않습니다. 소스코드에 키를 직접 넣지 않습니다.

## 라이선스 / 안내

정부가 공표한 공개 협정문을 비교 열람하기 위한 **내부 실무용 도구**입니다.
협정 원문의 권리는 각 원출처(정부·협정 당사국)에 있으며, 이 앱은 원문을 가공 없이 표시만 합니다.
표시 내용이 법적 효력을 갖는 정본을 대체하지 않으므로, 공식 인용 시에는 반드시 원 협정문을 확인하시기 바랍니다.
