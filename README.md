# FTA 디지털협정 조항 비교 서비스

한국이 체결한 여러 **FTA(자유무역협정)의 디지털 통상 조항**을 협정별로 나란히 놓고 **원문 그대로** 비교하는 웹 앱입니다.
**33개 주제**(관세 · 비차별 · 특송화물 · 종이 없는 무역 · 전자송장 · 전자인증 · 국내 전자거래 체계 · 전자 계약 · 사전 승인 금지 · 전자지급 · 핀테크 · 데이터 이전 · 컴퓨터 설비 위치 · 암호 ICT · 개인정보 보호 · 소스코드 · 온라인 소비자 보호 · 스팸 · 사이버보안 · 온라인 안전 · 인터넷 접근 · 정부 데이터 공개 · 디지털 정부 · 데이터 혁신 · 디지털 신원 · 인공지능 · 경쟁정책 협력 · 중소기업 · 디지털 포용 · 물류 · 표준 · 정부조달 · 과세 예외)를 다루며, 각 조항은 **영문 원문 + 한국어본**을 한 쌍으로 보여줍니다. (한국어본이 없으면 "번역 없음"으로 명시)

> ### 📌 현재 규모 — 협정 29개(발효 24 + 미발효 5) × 주제 33개 = **957칸 전부 판정**
> 대상은 **한국이 체결한 발효 협정 24개 전체 + 미발효(서명·타결) 협정 5개**, 주제는 **33개**입니다(6차에서 "재경부 소관만" 규칙을 해제 → 8차에서 디지털 무역 장의 남은 조문 유형 13개 추가 → 9차에서 특수 조문 3개까지 주제화 — 모두 사용자 결정). 조항이 있는 **265칸에 조문 269건**을 수록하고, 조항이 없는 **692칸은 "해당 조항 없음"으로 확정 표시**합니다. 수록 조문은 전부 정부 공식 원문과 대조 검증됨.

## 왜 만들었나

디지털 통상 조항은 협정마다 다른 문서에 흩어져 있습니다. 같은 주제라도 협정별 조문을 찾으려면 협정문 PDF를 각각 열어 조항을 찾고, 문서 편집기나 엑셀에 복사해 나란히 붙여놓고 대조해야 합니다.

| 현행 방식의 문제 | 이 앱의 해결 |
|---|---|
| **분산** — 협정마다 문서가 따로라 한눈에 못 봄 | 한 화면에 최대 4개 협정을 좌우로 배치 |
| **수작업 오류** — 복사·붙여넣기 중 조문 누락·오기 | 검증된 데이터를 그대로 렌더링 (사람 손 안 탐) |
| **영·한 짝 관리 번거로움** | 각 칸에 영문 원문 + 한국어본을 항상 한 쌍으로 |
| **버전 혼선** — 지금 보는 게 최신본인지 모름 | 조항마다 **데이터 기준 시점(baseline)** 라벨 표시 |
| **재현성 부족** — 같은 비교를 매번 처음부터 | 주제·협정만 고르면 누구나 동일 화면 재현 |

> 목표: 수작업으로 **20~30분** 걸리던 협정 3~4개 대조를 **3분 이내**로.

**주 사용자:** 재정경제부 내부 실무자 (확장: 통상 실무자·연구자 — 로펌, 연구기관, 무역 전공 대학원생 등)

**주제마다 성격이 다릅니다.**

- **과세 예외**는 거의 모든 협정에 있습니다(25/29, 없는 곳은 EFTA · ASEAN · 인도 · 싱가포르 DPA). **관세·특송화물·종이 없는 무역**도 18~20개 협정에 걸쳐 있습니다.
- **6·8·9차에 추가된 주제 대부분은 최근 디지털 협정에 몰려 있습니다.** 싱가포르 DPA · DEPA · UAE · 미발효 5개가 대표적입니다. **암호 ICT · 온라인 안전 · 디지털 포용 · 디지털 정부는 각 2개 협정뿐**이고, **전자 계약 · 사전 승인 금지는 EU DTA 하나**, **정부조달(디지털 관련)은 DEPA 하나**뿐입니다.
- 이렇게 보유 협정이 1~2개인 주제는 화면에서 대부분 "없음"으로 보이는데, 이는 **정상**이며 "어느 협정에 이 조항이 있는가"를 찾는 기능 3의 목적에 오히려 부합합니다.
- 2000년대 초기 전자상거래 장 협정에는 신설 주제 조항이 거의 없어, 화면에서 "없음"이 많이 보이는 것이 **정상**입니다.

**주제 범위 결정** (전부 사용자 결정 사항)

- **범위 개정 이력** — 1~5차는 "재정경제부 소관 주제만"(7개)이었습니다. **6차에서 이 제한을 해제**해 디지털 협정 전체로 넓혔고(+10개), **8차에서 디지털 무역 장의 남은 조문 유형 13개**를 담았으며, **9차에서 어느 주제에도 맞지 않던 특수 조문 3개**(전자 계약·사전 승인 금지·디지털 정부)까지 각각 주제로 세워 33개가 됐습니다.
- **정부조달** — **디지털 경제 관련 조항만** 담습니다. 전통 FTA의 정부조달 장 전체를 담으면 한 칸에 조문이 15~20개가 되어 좌우 비교가 무의미해지기 때문입니다.
- **경쟁정책 협력** — **디지털 무역 장 안의 경쟁 조문만**입니다. 중국·베트남·호주 등 7개 협정의 별도 「경쟁 장」은 대상이 아닙니다(같은 이유 — 장 전체는 비교 단위가 맞지 않습니다).
- **과세 예외** — 협정 전체에 걸리는 일반 예외라 엄밀히 디지털 통상 조항은 아니지만, 실무 가치가 커서 29개 협정 전부를 대상으로 수록했습니다.

> **여전히 범위 밖:** 통신·지식재산·금융서비스 등 **다른 장**의 유사 조항, 각 장의 **정의·적용범위·일반 협력** 조항. (8차까지 범위 밖이던 특수 조문 3개는 **9차에 주제로 편입**됐습니다.)

1. 협정 선택 패널과 조항 유무 배지에서 **「미발효(서명·타결) — 문안 변동 가능」 그룹으로 분리** (점선 구분)

> EU DTA는 디지털 전용 협정이라 **특송화물 조항이 없습니다**. 세르비아 CEPA(2026-05 타결)는 **협정문 미확보로 제외**했습니다.

## 주요 기능

### 1. 조항별 협정 비교 뷰
- 최대 **4개 협정**을 좌우로 나란히 표시 (1개만 고르면 한 칸만, 초과 선택 불가)
- 좌우 배치 순서는 **사용자가 고른 순서**를 그대로 따름
- 각 칸 = `조항 번호 · 기준일 라벨 · 영문 원문(EN) · 한국어본(KO)`
- 한 협정에 같은 주제 조항이 여러 개면 **누락 없이 모두** 조항 번호 순으로 나열
- 긴 원문은 앞부분만 접어 보여주고 **"더보기"**로 전체 펼침

### 2. 주제·협정 선택 + 원문 내 키워드 검색
- 주제는 **라디오(1개씩, 목록이 길어 자체 스크롤)**, 협정은 **선택 칩 + 추가 패널**(29개 규모 대응 — 이름 검색, "조항 있는 협정만 보기" 기본 켜짐, 최대 4개)
- **주제를 바꿔도 선택한 협정 목록은 유지** — 같은 협정 조합으로 서른세 주제를 이어서 비교
- 검색은 **현재 선택한 주제·협정 범위 안의 원문에서만** 수행 (전체 데이터 검색 아님)
- **부분 일치** 지원 (예: `무관세` → `무관세화`도 매칭), 영문은 **대소문자 구분 없음**
- 찾은 단어는 **노란 형광펜으로 하이라이트만** — 요약·해석 없음
- 검색어가 포함된 조항 카드는 **자동으로 펼쳐짐**

### 3. 주제별 조항 보유 협정 자동 찾기
- 주제를 고르면 **"협정별 조항 유무"** 영역에 조항을 가진 협정이 배지로 자동 나열됨
- 배지에는 **협정 이름만** 적습니다. 있음/없음은 ① 보유 개수 요약 문구(`「Customs Duties(관세)」 — 29개 중 20개 보유`) ② "없음" 협정을 따로 모아둔 **`▸ 조항 없는 협정 N개 보기` 접기 영역** ③ 배지 색상(선택 시 네이비) ④ `title`(마우스 오버 설명) ⑤ `aria-pressed`(스크린리더)로 전달됩니다
- **"있음 / 없음" 텍스트는 `＋ 협정 추가` 패널의 목록 항목에만** 붙습니다
- 배지를 누르면 그 협정이 바로 비교 대상에 추가/해제돼 비교 뷰로 연결됩니다 ("없음" 배지는 표시 전용)

### 4. 인쇄 / PDF 저장

- **「🖨 인쇄 / PDF 저장」** 버튼으로 현재 비교 결과를 그대로 종이에 뽑거나 PDF로 저장합니다
- **A4 가로**에 선택한 협정을 나란히 배치합니다
- 화면에서 접혀 있던 긴 원문도 **인쇄할 때는 전부 펼쳐** 나갑니다 (잘린 원문이 종이에 남지 않도록)
- **조항 출처는 화면과 인쇄물 모두에서** 볼 수 있습니다 — 화면은 카드 하단 접이식 「출처」 토글(기본 접힘), 인쇄물은 토글 없이 전문 표시 〔7차〕
- 인쇄할 내용이 없을 때(협정 0개 선택 · 검색 0건)는 버튼이 잠깁니다

### 5. 첫 화면으로 되돌리기

- 헤더의 **제목·로고를 누르면 첫 화면으로 새로고침**됩니다 — 고른 주제·협정·검색어가 모두 초기화됩니다

- **원문 검색은 화면 맨 위 헤더 오른쪽에 있습니다** 〔11차 · 사용자 제안 — 관세법령정보포털 상단 검색 방식〕. 검색창 오른쪽 끝은 아래 비교 뷰 오른쪽 끝과 맞춰져 있습니다.
- **주제는 화면 왼쪽 세로 목록(사이드바)입니다** 〔10차 · 사용자 제안 — 관세법령정보포털 좌측 메뉴 방식〕. 주제 33개를 가로로 늘어놓으면 화면 위쪽 24%를 먹고 그 안에서 또 스크롤해야 했습니다. 세로 목록은 33개가 한 줄에 하나씩 들어가고 **조항 영역이 세로 100%**를 씁니다. 목록이 길면 사이드바 안에서만 스크롤되고, 고른 주제는 항상 보이게 따라갑니다. 협정 선택·인쇄는 오른쪽 본문 위에 있고 스크롤하면 위로 지나갑니다. **창이 좁으면(≤1180px) 위쪽 가로 목록으로 자동 복귀**합니다.
- **협정 선택은 체크박스가 아니라 "선택 칩 + 추가 패널"** 입니다. 컨트롤 바에는 고른 협정만 칩으로 남고, 칩의 `✕`로 해제합니다. **칩의 좌→우 순서가 비교 뷰의 좌우 순서**입니다.
- `＋ 협정 추가`를 누르면 패널이 열립니다 — 협정 이름 **부분 일치 검색**(예: `베트` → 베트남), **"조항 있는 협정만 보기" 기본 켜짐**, 목록 각 항목에 현재 주제 기준 **있음 / 없음** 표시, 바깥 클릭이나 `Esc`로 닫힘, 4개가 차면 미선택 항목은 비활성.
- **조항 유무 배지를 눌러서도** 바로 비교 대상에 넣을 수 있습니다.
- **비교 뷰 칸 머리에만 정식 명칭**이 들어갑니다(`한-싱가포르 DPA` · `RCEP (역내포괄적경제동반자협정)` · `한-미국 FTA`). 칩·배지는 짧은 이름입니다.

| 상황 | 화면 동작 |
|---|---|
| 협정 0개 선택 | 비교 뷰 대신 **"비교할 협정을 선택하세요."** 안내 |

| 한국어본이 없음 | 그 칸의 KO 자리에 **"번역 없음"** 명시 (임의 번역 생성 안 함) |

## 🔒 원문 무결성 원칙 (이 앱의 신뢰성)

이 앱의 가치는 **원문을 손대지 않는 것**에 있습니다.

- 조항 원문(`text_en` / `text_ko`)을 **요약·수정·의역·재작성하지 않습니다.** 준비된 데이터를 그대로 표시만 합니다.
- **AI 요약·해설·해석 기능을 만들지 않습니다.** 이 앱이 하는 일은 원문 비교와 키워드 검색뿐입니다.
- 한국어본이 없으면 임의 번역을 만들지 않고 **"번역 없음"**으로 명시합니다.
- 원문은 **정부 공식 1차 출처(협정문 원본 PDF 등)에서 그대로 확보한 것만** 입력합니다. 검색엔진 요약·2차 설명 자료는 원문으로 쓰지 않습니다.
- 출처·기준일·보정 메모 등 주석은 **`source` 필드에만** 기록하고, 원문 필드에는 원문 외 어떤 표시도 섞지 않습니다.
- 조항 유무를 임의로 추론하지 않고, **데이터에 있는 그대로만** 판정합니다.

**출처 및 검증**

- **확보 방식** — 모든 조항의 영문·한국어 원문은 **산업통상자원부 FTA 포털**에 게재된 **장(章)별 국·영문 PDF**에서 직접 수집했습니다. 검색엔진 요약이나 2차 설명 자료는 원문으로 쓰지 않습니다.
- **1차 출처는 로컬 협정문 폴더** — 내려받은 협정문 PDF는 저장소 밖 `FTA 협정` 폴더에 두고 **이 폴더를 먼저** 봅니다(포털은 최종 검증용). 용량이 커서(66개 · 553MB) 저장소에는 커밋하지 않고, 대신 **파일별 SHA-256을 담은 [`agreement-manifest.json`](agreement-manifest.json)** 을 두어 **협정 개정으로 파일이 교체되면 어떤 조항을 다시 검증해야 하는지** 알 수 있게 했습니다 (`node scripts/agreement-files.mjs check`).
- **텍스트 추출이 불완전한 3개 협정**(칠레 · 인도 · EU)은 한때 **사용자가 원문을 직접 확인해 제공**한 값을 썼으나, 지금은 **셋 다 기계로 재검증**했습니다. EU는 기존 값이 정확했고, **칠레 2곳·인도 3곳은 오류가 발견돼 바로잡았습니다**(아래).
- **검증 결과 — 수록 조문은 사이클마다 전수 대조를 거쳤고 불일치 0건**입니다 (44건 → +6건 → +22건 → +27건 → 〔6차〕 +105건 → 〔8차〕 +61건 → 〔9차〕 +4건 = **269건**). 상세 결과는 [CHECK.md](CHECK.md)에 있습니다.
- **전수 기계 재검증 완료** — 기존 72건 × 영·한 = **144칸 전부**를 로컬 협정문 PDF와 기계 대조했습니다(텍스트 레이어 조각 대조 130 · 부호 OCR 확인 10 · 포털 장별 PDF 대조 5 · OCR 3중 검산 4). 발견된 정정은 **아포스트로피 모양 3곳**(`'`→`’`)뿐입니다. 캄보디아 `Minister's`는 원문 활자 자체가 곧은 모양이라 그대로 두었습니다 — **원문이 기준이지 통일이 기준이 아닙니다.**
- **미발효 5개 협정의 신규 27건도 전수 자동 감사 통과** — 27건 × 영·한 = **54칸 전부**를 순서 유지 조각 대조로 자동 감사해 **전문 일치**를 확인했습니다. 원문은 로컬 협정문 폴더의 전문 PDF와 포털 장별 PDF에서 기계 추출했습니다.
- 각 조항의 구체적 출처(문서명·추출 경로)와 특이사항은 데이터의 **`source` 필드**에 건별로 기록해 두었습니다.

**깨진 국문 PDF에서 원문을 되살린 사례 — 영국의 과세 예외**

한때 이 조항만 국문이 비어 있었습니다("번역 없음"). 정부가 배포하는 국문 파일이 **모두 폰트 인코딩이 손상**돼 텍스트 추출로는 한글이 나오지 않았기 때문입니다. 지금은 **OCR로 확보해 수록**했습니다. 다만 OCR 결과를 그대로 믿지 않고, **세 갈래로 교차 검산한 것만** 넣었습니다.

1. **OCR 3회** — 해당 쪽을 이미지로 렌더링해 배율 4·6·8로 각각 읽고 결과를 대조 (24줄 중 21줄이 세 번 모두 일치)
2. **깨진 텍스트 레이어와 대조** — 한글 코드는 깨졌어도 **글자 수·공백·줄바꿈 위치는 멀쩡**합니다. 이 구조에 OCR 결과를 맞춰 보면 OCR이 흘린 글자가 어디에 몇 자 있는지 드러납니다. 같은 쪽 안에서 얻은 글자 대응을 다수결로 확정해 **미해결 글자 0**으로 마감했습니다.
3. **승계 원조문과 대조** — 한-영국 FTA는 한-EU FTA를 승계한 협정입니다. 이미 검증 수록된 한-EU 제15.7조와 비교해 **낱말 일치율 93.2%**, 차이는 전부 당사자 표기(`유럽연합 회원국`→`영국`, `당사자`→`당사국`, `각자의`→`각국의`)뿐임을 확인했습니다.

> OCR은 줄 끝에 홀로 떨어진 한 글자를 통째로 버리는 버릇이 있습니다(`부여하는 데`의 `데`). 세 배율 모두 같은 자리에서 빠졌으므로 **OCR만 썼다면 못 알아챘을** 누락입니다. 2번 검산이 이를 잡아냈습니다.

**결과: 수록한 269건 모두 영문·국문을 갖췄습니다.** "번역 없음"으로 남은 조항은 없습니다.

**같은 방법으로 재검증한 3건 — 칠레 · 인도 · EU**

눈으로 확인해 입력했던 3건도 같은 방식으로 기계 검증했습니다. **결과가 갈렸습니다.**

| 협정 | 결과 |
|---|---|
| **EU** 제7.48조 제3항 | ✅ 영·한 모두 기존 값이 정확 |
| **칠레** 제20.3조 | ⚠️ 2곳 정정 — `"관세"` → `“관세”`, `효력을부여하기` → `효력을 부여하기` |
| **인도** 제5.5조 | ❌ 문장부호 3곳 정정 — 빠진 쉼표 2개(`규정하고,` `합치하도록,`)를 넣고, 없는 쉼표 1개(`서류,요건`)를 뺌 |

> **왜 눈으로는 틀리기 쉬웠나.** 인도·EU 협정문 PDF는 텍스트는 정상 추출되는데 **문장부호를 뒤 낱말 앞으로 밀어** 내보냅니다(`규정한다 .그리고`). 뷰어에서 복사해도 같은 값이 나오므로, 복사본을 보고 판단하면 **있는 쉼표를 놓치고 없는 쉼표를 넣게 됩니다.** 화면에 그려진 모습을 읽는 OCR이라야 잡힙니다.
>
> 칠레 국문 PDF는 **JBIG2로 압축된 스캔**이라 일반 PDF 라이브러리로는 빈 쪽만 나옵니다. Windows 내장 PDF 렌더러로 그려야 읽힙니다. 종전 값은 국가법령정보센터 웹 공포본에서 가져온 것이었는데, **웹 본문은 PDF 원문의 대체물이 아니라는 것**이 이번에 드러났습니다.

> 다루는 데이터는 정부가 공표한 **공개 협정문**뿐이며 대외비가 아닙니다. **개인정보를 수집·저장·처리하지 않습니다** (로그인 기능 없음).

하위 컴포넌트가 자기 화면만을 위해 갖는 UI 국소 상태는 4개입니다.

| 상태 | 위치 | 의미 |
|---|---|---|
| `pickerOpen` | `AgreementSelector` | `＋ 협정 추가` 패널 열림 여부 |
| `query` | `AgreementPicker` | 패널 안의 협정 이름 검색어 |
| `onlyAvailable` | `AgreementPicker` | "조항 있는 협정만 보기" (기본값 `true`) |
| `showUnavailable` | `AvailabilityBar` | "조항 없는 협정 N개" 접기 펼침 여부 |

> 조항 데이터(`articles`)는 상태가 아니라 `src/data/articles.json`을 **정적 `import`** 한 것입니다 — 빌드 시 번들에 포함되며 런타임에 바뀌지 않습니다.
> 협정별 조항 유무·비교 컬럼·하이라이트도 따로 저장하지 않고 위 상태와 `articles`로부터 **그때그때 계산**합니다.

## 배포 · 보안

정적 사이트이므로 어디에나 배포할 수 있습니다.

> 이 저장소는 **Vercel 프로젝트 `fta-digital-compare-next`에 연결**돼 있어 `main` 브랜치에 push하면 [자동 재배포](https://fta-digital-compare-next.vercel.app)됩니다. (1차 사이클 배포본은 별개 저장소 `fta-digital-compare`에서 관리되며 서로 영향이 없습니다.)

[`vercel.json`](vercel.json)이 포함돼 있어 배포 시 아래 **보안 응답 헤더 5종**이 적용됩니다.

| 헤더 | 값 |
|---|---|
| `Content-Security-Policy` | `default-src 'self'` 기반 (외부 스크립트·프레임 차단) |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `SAMEORIGIN` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Strict-Transport-Security` | `max-age=63072000; includeSubDomains` |

> 로컬 서버에도 같은 헤더가 적용됩니다([`vite.config.js`](vite.config.js)) — **`npm run dev`은 4종, `npm run preview`는 5종**. CSP는 HMR과 충돌하므로 **프리뷰·프로덕션에만** 적용됩니다. 즉 CSP 관련 동작은 `npm run preview`로 검증합니다.
> **비밀 정보(`.env` 등)는 `.gitignore`로 제외**되며 저장소에 올라가지 않습니다. 소스코드에 키를 직접 넣지 않습니다.
